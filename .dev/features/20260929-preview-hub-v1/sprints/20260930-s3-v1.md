## Goal and scope

- Outcome: a `/preview` command in a PR comment on a catalog repository creates, reports on, and deletes that PR's environment through the polling bot `phub-bot` inside the `preview-hub` VM, replying once per command; closing the PR removes the environment; unauthorized or fork commands run nothing.
- Target user: the owner (cafitac) working in PRs.
- Hypothesis: an outbound-only polling bot with a comment-ID ledger gives exactly-once command handling without runners, webhooks or host changes.
- Non-goals: GitHub App/webhooks, Actions runners, multiple hosts, ai-qa, notifications beyond the reply comment, any Earlypay code or configuration.

## Requirements and acceptance

- Requirements: R8 (PR comment bot) from `../feature.md`; regression of R1–R7, R9.
- Acceptance IDs: A9 (plus A1–A6, A8 regression through the existing E2E).
- A9 detail: (a) `/preview up` on an open same-repository PR of preview-example-backend -> exactly one reply with state READY, per-service commit and URL, the backend pinned to the PR head SHA; (b) `/preview status` -> reply with the current state; (c) `/preview down` -> environment deleted, empty label inventory; (d) closing a PR that has an environment -> environment deleted within two poll intervals; (e) the same comment is never executed twice (bot restart during the run, duplicated poll window); (f) comments from non-collaborators, fork PRs, closed PRs and malformed commands are refused with a reply and run nothing (unit fixtures; live only if a second account is available).
